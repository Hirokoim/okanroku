# 類似アプリ分析：位置情報×陣取り／収集ゲーム

往還録の「自動検知の積極活用」を検討するための参考資料。GPSを使った移動記録を陣取り・収集ゲームに変換している2つのアプリの構成を分析し、往還録への応用アイデアをまとめる。

対象は以下の2アプリ（いずれもApp Store掲載情報とWeb検索結果からの分析。App Store自体への直接アクセスができない実行環境のため、一次情報の全文までは確認できていない点に注意）。

- [散歩で日本開拓 - 歩いて地図を塗りつぶす位置情報ゲーム](https://apps.apple.com/jp/app/%E6%95%A3%E6%AD%A9%E3%81%A7%E6%97%A5%E6%9C%AC%E9%96%8B%E6%8B%93-%E6%AD%A9%E3%81%84%E3%81%A6%E5%9C%B0%E5%9B%B3%E3%82%92%E5%A1%97%E3%82%8A%E3%81%A4%E3%81%B6%E3%81%99%E4%BD%8D%E7%BD%AE%E6%83%85%E5%A0%B1%E3%82%B2%E3%83%BC%E3%83%A0/id6785751041)
- [KYRO: ランニング陣取りゲームアプリ](https://apps.apple.com/jp/app/kyro-%E3%83%A9%E3%83%B3%E3%83%8B%E3%83%B3%E3%82%B0%E9%99%A3%E5%8F%96%E3%82%8A%E3%82%B2%E3%83%BC%E3%83%A0/id6755943100)

## 1. 散歩で日本開拓

**コンセプト**：日常の移動（通勤・通学・買い物・お出かけ）で歩いた軌跡をGPSで記録し、訪れたエリアを地図上で自分の「開拓地」として塗りつぶしていくゲーム。

**構成要素**

- GPSトラッキング：歩数計ではなく位置情報ベースで移動軌跡そのものを記録
- 陣取り／塗りつぶし：訪問済みエリアが色付けされ、開拓の進捗が可視化される
- コレクション性：「日本全国を少しずつ制覇する」という長期的なゴール設計
- 記録の副産物化：近所の散策から旅行の記録まで、日常の移動ログがそのまま思い出記録になる

**設計の骨格**：単独プレイ・対人要素なし・受動的な記録型（歩けば自動で進む）。競争よりも「継続と収集」でエンゲージメントを作るタイプ。

## 2. KYRO（ランニング陣取りゲーム）

**コンセプト**：ランニングのコースが地図上でループ（自己交差）を描くと、その内側が自分の「領地」になるランニングアプリ。

**構成要素**

- 陣取りロジック：スタート地点への回帰は不要で、コースが自身と交差した時点で領地化
- 対人競争：他プレイヤーの領地を走り抜くことで奪える／奪われた土地は「クルーを呼んで」奪還可能
- ライブ大会場：人気コースでラップタイムが自動集計され、ベストラップ・周回数でランキング化
- ランク＋リワードシステム：13段階のランク、週間ストリーク、XPラダー
- ソーシャル機能：友達と一緒に走ると同じランとして自動記録

**設計の骨格**：対人・競争型・ソーシャル要素が濃い。陣地の「奪い合い」と「ランキング」でリアルタイムの緊張感を作るタイプ。

## 3. 両者の構成比較

| 観点 | 散歩で日本開拓 | KYRO |
|---|---|---|
| 想定運動 | 歩行（散歩） | ランニング |
| 陣取りの単位 | 訪問エリア（塗りつぶし） | 走行ループの内側 |
| 対人性 | なし（単独記録型） | あり（奪い合い・ランキング） |
| ゲームループの核 | 継続・収集（全国制覇） | 競争・防衛（領地維持） |
| ソーシャル | 見当たらず | 友達との合同記録あり |

共通しているのは「GPSで移動軌跡を取得し、地図上の面積・領域を自分のものとして可視化する」という基本アーキテクチャ。差はそこに載せるゲームループが「収集型（開拓）」か「対戦型（陣取り合戦）」かという点にある。

## 4. 往還録への応用検討

往還録は「静かな観察・原本としての記録」という性格が強く、KYROの対人競争（奪い合い・ランキング）要素はコンセプトとミスマッチと考えられる。相性が良いのは「散歩で日本開拓」の**自動記録・収集型**の考え方。

### 4-1. 既に要件定義書にある自動化構想（未実装分）

`docs/requirements.md` 6章Phase1に以下が既にある。今回の比較検討でも方向性は変わらず、まずこれらの完成が土台になる。

- 写真EXIFからのGPS・撮影日時の自動抽出
- 地点候補の自動提示（撮影GPSと`locations`比定地の距離計算→近い順に2〜3件提示）
- 複数写真の一括取り込み時の自動振り分け
- 天気の自動取得（訪問時点のスナップショット）
- 訪問ステータスの自動導出（`location_id`に紐づく`records`の有無で判定、手動フラグなし）

### 4-2. 新たに検討したいアイデア

**A. ジオフェンスによる解説の自動トリガー**
機能⑥「解説レイヤー」は現状「地点を開いたとき」に手動で読む設計。比定地に一定半径で近づいたら位置監視で自動検知し、「訪問前解説」を自動で出す→記録保存後に「訪問後解説（北斎の嘘の種明かし）」を自動で開示する流れにできる。訪問前と訪問後の出し分け（機能⑥）と相性が良い。

**B. クラスタ単位の「開拓マップ」表示**
散歩アプリの「塗りつぶし」を援用し、地図トップ画面でクラスタ（江戸市中・東海道・甲州道中…）ごとに訪問済み地点の割合を色の濃淡で塗る。46地点のピン一覧より「面」として開拓の進み具合が視覚的に分かる。進捗ダッシュボード（機能③）の可視化強化として位置づけられる。`docs/roadmap.md` Phase1タスク(A)「`locations.cluster`を埋める」と直結する。

**C. 経路ログの自動記録（往還そのものの可視化）**
現地モードで移動中のGPS軌跡を裏で記録し、地点間の「歩いたルート」を後から地図に描く。プロダクト名の由来である「往還（行き来した道）」を、点（地点）だけでなく線（経路）として残せる。KYROのループ検知に近い技術だが、対人要素は付けず「自分がどう歩いたか」の記録に留める。バックグラウンド位置取得の実装コストとバッテリー消費が課題になる。

**D. 定点観測の自動リマインド**
「次に行く予定」地点や季節が変わった定点観測地点について、位置情報またはカレンダーベースで「そろそろ再訪の季節です」と自動で知らせる。現状Phase1では通知は非実装だが、小さく効果が出やすい追加候補。

### 4-3. 優先度についての所感

BとAは既存の設計思想（机上／現地の二層構造、訪問前後の出し分け）に自然に乗るため着手しやすい。Cは「往還録」の世界観を強める目玉になり得るが、バックグラウンド位置取得の実装コストが課題。Dは小さく効果が出やすい追加。

まずは**B（開拓マップ表示）**が`docs/roadmap.md`の既存タスクとも直結するため、着手候補として有力。
