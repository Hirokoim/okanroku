# 往還録 開発ロードマップ（Phase1〜3）

`docs/requirements.md` 6章の開発フェーズ計画を、進め方の手順として読みやすく整理したもの。実データ（完了/未完了）は6章が正、こちらは**残りをどの順番で・どう確認しながら進めるか**の手引き。

## モックアップを作る/作らないの判断基準

すべての項目でモックアップを作るわけではない。以下で判断する。

| 作る | 作らない・直接実装する |
|---|---|
| ユーザーが直接触る新しい画面・新しい操作導線 | データベースのスキーマ変更・RLSポリシー |
| 見た目や情報の出し方に選択肢がある（配色・レイアウト・出し分け） | 既存画面への軽微な項目追加 |
| 一度決めると後から直しにくいもの（オンボーディングの流れ、导线の分岐） | 裏側の処理（EXIF抽出、天気取得など見た目に出ない部分） |

判断に迷ったら、「これは今すぐ見せられる形にできるか」で判断する。裏側の仕組みはコードを書いて動かして見せる。画面の見え方・使い勝手が絡むものはモックアップで先に合意してから実装する。

## Phase 1（MVP）：残タスク

**ゴール**：北斎46図に絞り、地点を地図で見て、現地で1件記録を保存できる状態にする。

データモデル・地図・地点詳細は完成済み。残っているのは「現地での記録入力」まわり。

| 項目 | モックアップ | 確認するタイミング |
|---|---|---|
| `locations.cluster`を手動で埋める | 不要（データ投入のみ） | 完了後、地図のクラスタフィルタで見え方を確認 |
| 記録フォームへの`location_id`連携（地点選択） | **要**：候補提示のUI（前に見せた「近くの地点」カード）は既にモックアップ済みなので、それをベースに実装してよい | 実装後、実際の写真で地点候補が正しく出るか確認 |
| 写真EXIFのGPS自動抽出・代替入力 | **要**：GPSが取れなかったときの代替入力（地図タップ／現在地取得）の画面遷移だけ先に見せる | EXIF成功時・失敗時の両方を実データで試してから次へ |
| 複数写真の一括取り込み動線 | **要**：「5枚の写真は3地点ぶんのようです」の分岐確認画面 | 実際に3地点分の写真をまとめてアップロードして確認 |
| 天気の自動取得 | 不要（裏側の処理） | 保存後、天気が記録に入っているか確認。取得失敗時に保存がブロックされないことも確認 |
| 入力中データの一時保持 | 不要 | 入力途中でタブを閉じて再度開き、内容が残っているか確認 |
| 簡易進捗ダッシュボード | **要**：数字の見せ方（訪問済み/46、クラスタ別内訳の並べ方）を先に見せる | 実データで数字が合っているか確認 |

**進め方の目安**：`location_id`連携 → EXIF抽出 → 複数写真の取り込み、の順で進めるのが自然（後のものが前のものに依存する）。天気・一時保持・ダッシュボードはこの3つと並行で進めても支障はない。

## Phase 2：現地記録の充実・複数ユーザーの解禁

**ゴール**：現地での記録がストレスなく行え、蓄積が資産として見え、他ユーザーとも記録を見せ合える状態にする。

| 項目 | モックアップ | 確認するタイミング |
|---|---|---|
| 他ユーザーの公開記録閲覧（機能⑤） | **要**：地点詳細画面に他ユーザーの記録がどう並ぶか | 2人目のテストアカウントで公開/非公開の切り替えを確認 |
| 解説レイヤー（機能⑥） | **要**：既に第26景でトーン比較を実施済み。まず1地点を完成させてから残り45地点へ | 1地点で「面白いかどうか」を確認してから広げる（要件定義書に明記済み） |
| 元絵の並列比較表示 | **要**：現地写真と元絵を並べる画面 | 実際の現地写真（無ければダミー）で見え方を確認 |
| 音声メモの録音＋文字起こし | **要**：録音ボタンの状態遷移（録音中／文字起こし中／完了） | 実際にスマホで録音して精度を確認 |
| 定点観測地点の再訪比較表示 | **要**：同じ地点の複数記録をどう並べるか | 同じ地点で2件以上の記録がある状態で確認 |
| 記録のMarkdownエクスポート | 不要（出力形式の確認のみ） | 出力したMarkdownをnoteに貼って崩れないか確認 |
| 進捗ダッシュボードの拡張 | **要**：グラフの種類（円グラフ／棒グラフ等） | 実データで確認 |
| 伊能忠敬・松尾芭蕉のデータ追加 | 不要（データ投入） | 追加後、機能⑤-Aのアクセス権と合わせて動作確認 |
| 人物ごとのアクセス権（機能⑤-A） | **要**：人物選択画面・アクセス権が無い人物の見え方（現在の設計では完全非表示） | 上記の人物追加と同時に、SQL（`docs/sql/`ステップ12）を適用してから確認 |

**進め方の目安**：まず解説レイヤーを1地点だけ試して面白さを確認（ここが一番「作ってみないと分からない」部分）。並行して伊能忠敬または松尾芭蕉のデータ投入とアクセス権機能を進める。他ユーザー公開機能は最後で良い（1人目のデータが十分貯まってからの方が確認しやすい）。

## Phase 3：プラットフォーム化

**ゴール**：より多くの巡礼者を受け入れられる基盤へ拡張する。

| 項目 | モックアップ | 確認するタイミング |
|---|---|---|
| 新規ユーザー獲得・オンボーディング施策 | **要**：初回起動時の導線 | 実際に第三者に触ってもらって確認 |
| AR・位置情報を活用した表示 | **要**：技術検証を兼ねた簡易プロトタイプが実質モックアップになる | 現地での実機テストが必須 |
| データ基盤（歴史資本MCPサーバー構想）への連携 | 不要（技術検証） | 連携先の要件が固まってから着手判断 |

Phase3は現時点で詳細設計するには時期尚早な項目が多い。Phase2が一段落してから、この一覧をもとに優先順位を相談する。
