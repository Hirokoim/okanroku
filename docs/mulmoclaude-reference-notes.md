# MulmoClaudeを参照するときのガイド

往還録は、MulmoClaude（`~/mulmoclaude`）上の`fugaku-36`コレクションのデータ・デザインを参考にしながら開発している。このドキュメントは、その参照作業をこれから行う人（人間・AIエージェント問わず）向けの手引き。

## 前提：2つのアプリは別物

MulmoClaudeの`fugaku-36`は**単一ユーザー**（ひろこさん本人）が使うローカルツール。往還録は**複数ユーザー**が使う公開Webアプリ（Supabase＋RLS）。同じ北斎データを扱っていても、設計思想は別物として扱う。

- MulmoClaude側：1つの地点＝1つのJSONファイルに、比定地・訪問ステータス・訪問日・写真まで全部同居
- 往還録側：「誰が見ても同じ情報（比定地）」と「ユーザーごとに違う情報（訪問記録・写真）」を別テーブルに分ける

**MulmoClaude側のデータ構造をそのまま真似ない。** 便利に見えても、それは単一ユーザー前提だから成立している形である場合が多い。

## 参照する前に確認すること

### 1. ビューファイルが実在するか

参照したい画面について、対応するソースファイルが`~/mulmoclaude/data/skills/fugaku-36/views/`にあるか、`find`や`ls`で確認する。無い場合、その画面は`schema.json`から自動生成されている（後述）。

### 2. ソースコードか自動生成かを見分ける

| 種類 | 見分け方 | 参照できる範囲 |
|---|---|---|
| 生のHTML/CSS/JS（例：`views/map.html`） | ソースファイルが存在する | 配色・レイアウト・マーカーデザインなど**見た目だけ**。ロジックはMulmoClaude独自のAPI（`window.__MC_VIEW`、写真取得エンドポイント等）に直結しており動かせない |
| `schema.json`からの自動生成（例：詳細モーダル） | ソースファイルが存在しない | フィールドの並び・レイアウトの構成のみ。コードは無いので流用不可 |

### 3. `schema.json`は設計図であり、実データの保証ではない

`schema.json`にフィールドが定義されていても、実際のデータ（`data/fugaku-36/items/*.json`）でそのフィールドが埋まっているとは限らない。**必ず実データのJSONファイルを直接読み、値が実際に入っているか確認してから設計に取り込む。**

また、フィールド名は`schema.json`と実データで食い違うことがある（運用しながら変わったため）。schemaの名前だけで判断せず、実データのキー名を確認する。

## データを流用する際の注意

### 画像・メディアファイル

MulmoClaude側にあるファイルをそのまま使わない。EXIF/XMPメタデータや取得元URLが残っていない画像は、著作権的な出所を説明できないため、公開アプリには使えない。**元絵などの画像は、パブリックドメイン宣言のある提供元（美術館のOpen Access等）から個別に取得し、取得元を記録する。**

外部APIやデータソースを使う場合も、「フィールドの値が正しそうに見える」ことと「実際にリンク先が有効である」ことは別問題。URLは実際にアクセスして確認する。

### 用語・命名

日本語の用語やラベル文言は、データ構造とは切り離して積極的に踏襲してよい（例：分類の呼び方、地名の切り方）。北斎作品世界の語彙は、MulmoClaude側で既に実用を通じて練られているため、作り直す必要はない。

## 作業の進め方

1. 参照したい情報がどこにあるか、実在を先に確認する（無いものを探しに行かない）
2. ソースか自動生成かを見分け、流用できる範囲を判断する
3. 実データを直接読み、schemaの定義を鵜呑みにしない
4. データ構造は複数ユーザー設計の観点で必要なら組み直す。用語・文言はそのまま活かせないか検討する
5. 外部から取得するデータ（画像URL等）は、実際にアクセスして有効性を確認してから投入する
